# lingximanju · 无限画布 × 智能体制片流水线

> 一个**全量自主编写**、零第三方依赖、可本地独立运行的 AI 影像创作工作台。
> 方法思想参考 ViMax 论文（[arXiv:2606.07649v2](https://arxiv.org/abs/2606.07649)），交互范式参考 Toonflow 的无限画布；未复制任何一方源码，详细参考依据见 [`docs/DEVELOPMENT.md`](docs/DEVELOPMENT.md)。

## 快速开始

```bash
cd lingximanju
./start.sh          # 或： node server.mjs
# 打开 http://127.0.0.1:45367
```

无需 `npm install`、无需构建、无需 API Key。首次打开先落在**项目列表页**：上方是「从小说到成片 · 六步走完一部漫剧」的图文流程说明，下方是全部项目卡片（搜索 / 筛选 / 排序 / 复制 / 导出 / 删除 / 继续创作）。若文本大模型或本地 ComfyUI 工作流尚未配置，会先弹「首次使用 · 配置创作模型」引导框，可「去配置模型」或「先跳过」——跳过不影响体验，内置 Mock 模板能完整跑通所有流程，项目列表页顶栏始终保留 **⚠ 模型未配置** 入口随时补配（项目会话内不显示应用级入口）。

点开内置示例「雨夜侦探 · 待运行骨架」后，顶栏 **▶ 运行完整流水线** 可看到画布随智能体执行自动生长：8 个骨架节点 → 40 个节点（事件、场景、镜头规格、关键帧、VLM 择优、视频片段、转场锚点）。

默认端口 **45367**，刻意避开 3000 / 4173 / 4174 / 5000 / 5173 / 8000 / 8080 / 8188 等常见开发端口，也避开操作系统临时端口段（49152–65535），降低与其他服务冲突的概率。

- 自定义端口：`PORT=8080 node server.mjs`（或 `PORT=8080 ./start.sh`）。
- 端口被占用时默认**自动向后顺延**最多 10 个端口，控制台会打印真实地址，同时写入 `data/.port`；`STRICT_PORT=1` 可关闭顺延（占用即报错退出），`PORT_SCAN=20` 可调整尝试次数。
- `HOST=0.0.0.0` 可允许局域网访问（默认仅 `127.0.0.1`）。

### 四视图导航与状态联动

| **无限画布** `canvas` | 顶栏 **⬡ 画布**、快捷键 `V` | 顶部范围条切换 **全部组合画布 / 项目主画布 / 每一集的独立画布**；节点级编辑、连线、自动布局、完整流水线运行 |
| **剧集详情** `episode` | 工作台分集列表 / 章节映射 / 项目管理「分集」Tab 点某一集 | 拆分原文、本集剧本、出场角色、每段分镜板（版式可选）、资源链接无限画布、单集导演包 / ComfyUI 视频 |

**项目会话**：打开项目后整页只讲当前项目。**退出出口统一为两处**：顶栏右上角「⇦ 退出项目」与左侧「项目设置 → 退出项目」，二者都走 `requestExitProject() → closeProject()`，清空项目态、画布、弹窗、日志与检查器再返回项目列表；项目卡 ✕ / `⌂ 项目列表` / 剧集面包屑「关闭项目」/ `H` 快捷键等旧出口已全部移除。列表页的「↩ 继续「…」」可一键回到刚关闭的项目。`V` = 工作台 / 画布互切、`Esc` = 从剧集详情返回。后端每次产物落盘都广播 `episode:update` / `episode:progress` / `character:batch` SSE，剧集详情页会静默重拉并保留当前标签页，工作台与首页同步刷新进度，无需手动 F5。

> **项目内整页项目化：全部与当前打开的项目相关**。顶栏是项目封面 / 可编辑项目名 / 六步进度 / 右上角「⇦ 退出项目」+ 本项目操作（工作台 / 画布 / 项目管理 / 运行 / 导演包 / 导出 / 本项目资源库），**不再出现**「⌂ 项目列表 / ⚙ 全局设置 / ☀ 主题 / ? 帮助 / ⚠ 模型未配置」等应用级入口；浏览器标签标题、状态栏 Provider（`本项目 · …`）、画布空态引导、剧集面包屑都带当前项目名。侧栏品牌与页脚、资源库入口（默认「仅本项目」，可一键退出看全库）同样只讲本项目；左侧是项目卡与六步进度、**项目导航**、**项目资源列表**（按 `/assets/` 引用归属，覆盖封面 / 角色定妆图 / 分镜板 / 视频 / 导演包）与**项目设置**（项目信息、创作设定、角色、交付物、封面、模型与运行、导出、退出项目，右上角 `◐` / `?` 可切主题、看本项目操作指引）。
>
> 内容同样项目化：所有 AI 入口的模型下拉按「项目 + 入口」分别记忆（显示「本项目默认模型」，切项目 / 关闭自动恢复，互不串台）；设置弹窗标题带项目名、运行参数随项目保存；帮助弹窗改为本项目操作指引并展示本项目 `x/6 步 · N 集 · M 节点`；画布视图的模板标注「当前」、节点库显示本项目各类型节点数、智能体只列本项目在用的（附节点数）。项目列表、新建、导入与应用级设置 / 主题 / 帮助统一收敛到项目列表页；项目内 `T` 切主题、`?` 打开本项目指引。关闭后顶栏 / 标题 / 状态栏恢复中性文案（`⌂ 项目列表`、`共 N 个项目`），不残留上一个项目的名称、模型、节点数或 Provider。产物落盘后侧栏资源列表由 SSE 防抖刷新。

上传支持**一次选多个 .txt/.md 文件**：合并时按文件生成全局唯一章号，拆分后把每个文件、每一章关联到对应剧集（工作台显示「文件 / 章节 → 剧集」映射）。在「角色」页可用 **✦ 一键生成全部角色定妆图**（可选三视图 / 只补缺失），逐张落盘并广播进度。每集可单独导出 `*.mmxpack.zip` 导演包，或以本集首张分镜板为首帧调用本地 ComfyUI 生成该集视频片段。

全局模型配置保存在 `data/app-settings.json`（已加入 `.gitignore`，API Key 不回传浏览器），一次配置对所有项目生效；项目设置里显式填齐的配置优先覆盖全局。

深链支持 `?new=1` 直达新建向导、`?project=<id>[&ep=<no>]` 直接落到工作台或某一集。

### 新建创作项目：只填一个名字

在项目列表页点 **＋ 新建漫剧项目**（或按 `N`），向导只有两项：

1. **项目名称（必填）** — 唯一必填项，空名称无法创建（前后端双重校验）
2. **一句话故事构想（选填）** — 之后 AI 补全项目信息、AI 生成小说都以它为创作依据

其他一切——小说正文、分集策略、角色、风格画幅、交付物、创作设定——**全部后置到项目工作台**，可以边做边补，也可以让 AI 一键补全。交付物默认「成片视频 + 导演包」，随时可改。

创建后**直接进入项目工作台**（不是画布）：

- **页面主体就是项目信息**：封面、名称、一句话简介、类型 / 受众 / 基调、画面风格 / 画幅 / 交付物，全部就地编辑；「✦ AI 补全信息」按一句话构想补全空白字段（**只补空字段，不覆盖你手改的内容**，未配置模型时用内置模板并明示来源）。
- **左侧是完整的漫剧生成路线图**，把六步任务换成友好外壳，每步都可点开对应操作台：

| 路线图 | 底层步骤 | 操作台能做什么 |
|---|---|---|
| ① 准备故事 | `upload` | **上传小说**（.txt/.md / 粘贴 / 示例，自动解析章节）或 **✦ AI 生成小说**（构想 → 分章大纲 → 可编辑 → 逐章生成全文 → 自动分集注入，等价完成 ①②） |
| ② 分集拆解 | `episodes` | 按章节 / 字数 / 场景段落三种策略 + 每集目标字数 + 最多集数，一键重新分集，下方实时列出每集摘要与钩子 |
| ③ 剧本创作 | `script` | 执行本步，编剧智能体把分集梗概写成统一格式剧本 |
| ④ 角色与上下文 | `context` | **提取角色**（全书 BM25 召回 + 候选名原文窗口取证 → LLM 优先 / 启发式兜底，证据引用逐字校验，零 Key 明示占位来源并显示候选/片段/证据统计）、角色卡一览、跳转角色管理生成三视图定妆；同时跑原著 RAG 与事件→场景→镜头分解 |
| ⑤ 分镜与画面 | `storyboard` | **只出分镜提示词 + 分镜图**：best-of-2 择优、机位锚点传播；**分镜画面设置**（九宫格 / 六宫格 / 四宫格 / 条漫四联 / 二十五宫格 / 单图 · 画幅 · 格内信息 · 构图参考 · 提示词公式）决定版面后，用真实关键帧合成每段**分镜板**；视频片段留给第⑥步 |
| ⑥ 视频与交付 | `deliver` | 画面全部定版后才逐镜头调 ComfyUI 出视频，再拼成片 MP4 / 导出 `*.mmxpack.zip` 导演包；只打包时跳过视频渲染 |

- **左侧还有故事来源与项目资源**：一眼看到《书名》章数字数集数、角色 / 分集 / 镜头 / 片段计数、角色头像；「⇧ 上传小说」「✦ AI 生成小说」始终可用（重新上传或重新生成会覆盖分集并重算 ①②）。
- **画布没有消失**：顶栏「⬡ 画布 / ▦ 工作台」或快捷键 `V` 随时切到无限画布做节点级编辑，切回来进度与状态同步。

「▶ 执行下一步」(`S`) 或「⏩ 全部执行」逐步推进，画布节点随每步生长。**灰=待执行、橙+呼吸光晕=进行中、绿✓+耗时=完成、红=失败可重试**，另有 `x/6` 胶囊、顶部进度条、画布上方六步导航条、Toast 与运行日志。每步的论文依据见 [`docs/THEORY.md`](docs/THEORY.md)。

> **AI 生成小说**：`POST /api/projects/:id/novel/ai`，`mode=outline` 只出大纲（可编辑），`mode=full` 逐章生成正文并 `attachSource` 注入（自动分集、播种角色、标记 ①② 完成）。配置 OpenAI 兼容模型后由 LLM 撰写；未配置时用主题化内置模板生成可演示的完整章节，响应里以 `source: mock | llm | fallback` 明示来源。

### 分镜画面设置：九宫格不再是唯一答案（⑤ 步）

故事板不是只有九宫格。调研过行业惯例（分镜板每格要带景别 / 机位 / 运动 / 时长 / 动作，而不只是序号）与 AI 漫剧的多宫格实践后，第⑤步的版面从写死的 3×3 变成**可配置的画面设置**：

| 版式 | 格数 | 适合什么 |
|---|---|---|
| 九宫格 3×3 | 9 | 动作序列、蒙太奇段落（默认） |
| 六宫格 3×2 | 6 | 对话场、需要更详细构图的场景 |
| 四宫格 2×2 | 4 | 关键瞬间、提案与评审页 |
| 条漫四联 4×1 | 4 | 竖屏条漫、连续动作横带 |
| 二十五宫格 5×5 | 25 | 整集总览、角色一致性检查 |
| 单图 1×1 | 1 | 定版镜头、封面级单帧 |

除版式外还可调：**画幅**（跟随项目 / 16:9 / 9:16 / 1:1 / 4:3，单格画幅恒等于成片画幅，换版式不会把格子拉成长条）、**格内说明条**（镜头规格 + 动作 / 只要动作 / 提示词 / 无）、**构图参考线**（三分线 / 中心十字）、**序号与署名**开关、**格图来源**（真实图优先 + 剪影占位 / 只排真实分镜图 / 纯示意），以及**提示词公式**五个开关（景别·机位·运动 / 出场角色 / 风格锚点 / 空间连续性 / 画幅说明）——提示词公式这组开关直接决定关键帧 prompt 里出现哪几段，而不是拼个空字符串。

- **保存设置**只落盘、不动产物；**⌗ 保存并重排分镜板**会按当前设置把全项目分镜板重排一遍（纯 SVG 拼接，不重跑图像模型、不烧 GPU）。
- 面板下方式**分镜板画廊**：每张板显示集 / 段、格数与版式徽标，点开放大看单格说明与真实图，可下载。
- **任务状态看板**：本步顶部实时列出**已经发送的任务与正在进行的任务**，四档严格分开：`进行中`（真的在 GPU 上算）／`已发送 · ComfyUI 排队中`（ComfyUI 已收下、等它出图）／`本次运行 · 等待发送`（已排进本次运行的计划，但受并发上限约束还没提交——调度器一启动会把整批目标标成 queued，这一档就是过去被误显示成「已发送」的那部分）／`待发送`（还没被任何一次运行接纳）。判定只看实证：节点上拿到 **prompt_id**（或提交时间戳）才算已发送，所以页头的「ComfyUI 排队 N」和 ComfyUI 队列里的条数是对得上的。每行给出发给生成后端的类型（关键帧 / 择优 / 视频 / 转场）、镜号与景别、提示词摘要、进度百分比、已用时 / 本次耗时、状态药丸与失败原因；接了本地 ComfyUI 时还带 **prompt_id**（点击复制，可直接去 ComfyUI 的队列 / 历史里复查）。看板数据直接来自画布节点的 `status / progress / meta.queuedAt / meta.startedAt / meta.submittedAt / meta.finishedAt`，SSE 推送即时更新、每秒刷新已用时，刷新页面后依然可查；`↻ 重出本镜`、`▶ 执行本步`、`全部执行` 发出的任务都会出现在这里。
- 「只排真实分镜图」是诚实模式：该段没有真实关键帧时格子画虚线框 + 「待出图」，页脚写「真实分镜图 0/N 格」，绝不把剪影占位说成已出图。
- **ComfyUI 任务对账（`⟲ 检查已完成`）**：ComfyUI 是独立进程，服务重启 / 请求中断 / 手动停止之后，它的队列与历史仍然在，而画布节点会停在「已发送 · 排队中」。点这个按钮会去 ComfyUI 核对一遍：**已完成的直接下载产物写回节点**（关键帧候选 / 视频片段 / 转场锚点），**仍在排队或执行中的保留状态、绝不重发**，只有 ComfyUI 侧也查不到结果的才复位成待执行，并询问是否**只重发这些**。`▶ 执行本步` 与 `↻ 重试本步` 也会先走同一套对账，所以中断后重跑不会再无条件重烧已经出好的图。
  - 认领顺序：① 节点上记录的 `prompt_id` 精确命中 `/history` → ② 命中但执行失败则照实标红 → ③ 仍在 `/queue` 的保留状态 → ④ 老任务（升级前没记 `prompt_id`）按 `/queue` 里的产物前缀 + 镜号认领（**已经在算的任务绝不再发一遍**）→ ⑤ 历史里按 `lingximanju_keyframe_<镜号>_…` + 排队时间窗兜底 → ⑥ 都没有才判「查无结果」。
  - 打开第⑥步时会自动做一次静默自检（15 秒内最多一次；项目正在运行时服务端直接跳过），把上一次被中断的运行留下的残留节点理清楚：能取回的取回、查无结果的转「待发送」，不用手动点按钮也不会一直挂着「排队中」。
  - 兜底匹配宁缺毋滥：转场前缀不带镜号，同类型同时残留多条时不猜测配对，直接判丢失重发，避免把 A 段的画面挂到 B 段。
  - **30 分钟追认窗口**：判过「查无结果」的节点会被记住（`meta.lostAt`），若 ComfyUI 随后才把它跑完，下一次对账 / 下一次执行本步会直接把结果追认回来，不会因为「刚复位完就出图了」而白烧一遍。
  - 一次执行结束时若仍有任务在 ComfyUI 侧未完成，会起**后台观察**自动取回（最多 30 分钟），不需要守着页面再点一次生成。
  - 接口：`POST /api/projects/:id/comfy/reconcile`，`{resubmit:true}` 时对查无结果的节点重新发送。
- 接口：`GET /storyboard/sheets` 出计划（几版式、几张板、几张真图、几张板已过期），`POST /storyboard/sheets` 保存并重排；业务口径收在 `storyboard-sheets` 智能体，详见 [`docs/AGENTS.md`](docs/AGENTS.md) §12。

### 分集制作：第③步之后，按季按集顺序走完 ④⑤⑥⑦

分季分集完成后按**顺序制作**：默认第一季第一集，四段 ④⑤⑥⑦ 全部完成 → **定稿** → 自动进入同季下一集；本季全部定稿 → 进入顺序里的下一季第一集。每一集有**自己的本集剧本、出场角色关联、分镜板与成片**；角色设定与定妆图是唯一例外，全书共享、同名角色按角色 ID 直接复用。项目级六步状态机保持不变（demo / 导演全流程 / 骨架项目照旧），每集进度记在 `ep.steps[stepId]` 与 `ep.finalized`（episode record 自带），互不覆盖。

| 按集步骤 | 做什么 | 产物 |
|---|---|---|
| ④ 剧本创作 | 生成本集剧本（带上一集结尾 / 本集钩子 / 本集原文 / 出场角色），可人工精修 | `ep.script` |
| ⑤ 角色与上下文 | 角色库为空时先自动提取全书角色；出场角色按原文姓名 / 别名匹配（手动关联不覆盖）；确认本集上下文 | `ep.characterIds` + `ep.steps.context` |
| ⑥ 分镜与画面 | 本集原文分段 → 逐段生成分镜板；可选 `comfy:true` 逐格调用 ComfyUI 补真实画面（已有图不重烧） | `ep.segments[].gridUrl` + 每格物料 |
| ⑦ 视频与交付 | 逐格视频（首帧 + 精确 videoPrompt → ComfyUI，已有片段自动跳过）→ **拼接本集成片 MP4**（与项目成片同一套 ffmpeg 归一 / 封顶 / 实测口径）→ 单集导演包 | `cell.video[]` + `ep.film` + `ep.pack` |

- **顺序队列（单一真源）**：`project-model.js` 的 `episodeQueue / defaultEpisode / nextPendingEpisode / seasonFinalProgress / markFinalized / episodeStagesDone / canFinalizeEpisode`——基于 `seasonGroups` 按「季升序 → 季内集号升序」展平，手动移季的集也正确入队；集号仍全局唯一，季只是分组视图；老项目无 `season` 全归第一季、无 `finalized` 视为未定稿。
- **当前剧集（季 + 集两级）**：季下拉（显示每季定稿数）+ 该季的集下拉 + 按队列跨季的上一集 / 下一集 + 四段进度 + 顺序制作位，整块控制区在**第③步「分季 · 分集」卡片内**。按项目记在 `localStorage`；导航条、控制区、流水线、说明条、区头、单集执行与剧本生成共用一个 `ui.activeNo`。切换剧集时剧本展开 / 编辑草稿 / 成片倍速 / 分镜灯箱按集存档、切回还原，**各集界面与产物完全独立**；④ 剧本台默认只显示当前集，其余集收进折叠列表。允许手动跳集，顺序只决定默认推进。
- **当前剧集不再悬浮**：身份直接写在「左侧面板 ↔ 右侧工作台」之间的**制作步骤窄栏**里——展开态显示紧凑标签 `第1季-1`（无空格、连字符；集号沿用全局唯一编号，第二季首集写 `第2季-4`），收起态 40px 状态轨把同一串拆成「第1季 / -1」两行，窄屏 ≤1080px 的横向步骤条改成一行常驻。短标签由 `project-model.js` 的 `episodeLabelShort()` 单独提供，**其它位置仍用完整中文「第 1 季 第 1 集」**。原顶部 sticky 常驻条已去掉 `position: sticky / z-index / 覆盖阴影`，改为分集卡内的普通控制带，跟随内容滚动、不再压住步骤卡；63 个 `data-act` 功能入口一个不减。
- **定稿与锁定**：四段全完成后，顶部条 / ③ 说明条 / 流水线面板出现「✓ 定稿本集并进入下一集」→ 写 `ep.finalized = {at, season, no}`（`ctx.onFinalizeEpisode` 走 mutate + `persist(true)` 落盘）→ 自动切到下一集并跳回第 ④ 步。已定稿集的行显示 🔒、四段执行与批量补齐全部禁用、区头主按钮变「🔒 本集已定稿」；后端 `runEpisodeStep(s)`、剧本生成 / 编辑接口一律拒绝，防止绕过界面覆盖产物。需要返工点「↩ 撤销定稿」（二次确认）。
- **角色是唯一例外**：`management.characters`（角色设定与定妆图）是项目级共享资源，**已存在则沿用**——切集、跨季、`force` 重做、定稿 / 撤销都不会重新提取，也不为每集另建一套；不同集出现同一角色时直接复用设定与定妆图。只有角色库为空时，首次执行 ⑤ 才提取一次全书角色，之后所有集共用。每集独立的只是 `ep.characterIds`（本集出场哪几位）。第⑤步顶部有共享角色库说明卡，执行结果 note 里写明「沿用项目角色库 N 位（不重新提取）」。
- **工作台入口**：第③步分集完成后出现「分集之后怎么走 · 顺序制作」说明条（项目级 ①②③ / 剧集级 ④⑤⑥⑦ / 角色例外 / 顺序规则、每季定稿进度、制作队列、当前制作位与定稿按钮）；第④步之后各步顶部是同一张「▥ 剧集流水线」卡——**按季分组、每集一行，横向摊开四段任务**，点集名即选中该集，行内只展开这一集的四段任务与「下一步」；「下一步」永远取四段里第一个未完成的阶段，不会跳段。批量只补「这一段的未完成集」且跳过已定稿集，单集失败不阻断后续。分季分集卡每集标「🔒 已定稿 / ● 当前制作位 / 待制作」并可一键设为当前集。
- **层级不再靠猜**：步骤导航在「分集拆解」与「剧本创作」之间有一条「以下按集执行」分界；④⑤⑥⑦ 的区头挂「剧集级 · 第 1 季 第 2 集 · 第 N/4 段」标签，区头主按钮只跑当前剧集，项目级整跑收进左侧导航的「执行下一步 / 全部执行」并附说明。
- **剧集标签统一中文**：界面上不再出现 `EP 02`、`S01`、`S01E02` 这类英文缩略，季和集一律写全，例如「第 1 季 第 1 集」；季下拉、集下拉、当前剧集主标识、制作队列、定稿提示、流水线行、分季分集卡、区头、剧本台、剧集详情页都走 `project-model.js` 的 `seasonLabel / episodeNoLabel / episodeLabelFull / queueItemLabel`。集号沿用全局唯一编号（季只是分组视图），因此第二季首集会写成「第 2 季 第 4 集」。
- **全局样式统一 · 界面精简（功能零删减）**：`public/styles.css` 建立共享设计令牌 `--radius-* / --sp-* / --fs-* / --btn-h`，`.pv-* / .sx-* / .sw-* / .fl-* / .epb-* / .ax-*` 六大组件族的圆角、内距、字号统一走令牌；补齐此前「用了 78 次却没定义」的 `.btn.sm`，并新增 `.btn.xs / .btn.ghost / .btn.block` 与状态胶囊统一基线。「分季 · 分集」从自带 `max-width:1460px + padding` 的页面级容器改为与工作台同构的标准 `.pv-card + .pv-card-head`，消除卡中卡与双重内距，统计条 / 季面板 / 集卡层级一致。第③步把顺序说明细则、章节映射、分季·定稿·角色库说明，以及季头和集卡的次要操作收进 `<details>` 折叠区，每张卡只留一个主行动 +「更多操作」——**所有 `data-act` 入口、筛选、批量、导出、定稿一个不删**，由 `tests/ui-style.test.mjs` 用 63 个动作基线集合锁死。

- 每集失败 / 预检不通过都会如实落 `error` 并给出「先做哪一步」提示（例：本集还没有带真实画面的分镜格）；成片只认 ComfyUI 真实片段拼接，静态图不冒充成片。

工作台改为**四个 Tab**，首屏只显示概览，复杂内容按需进入；顶栏次要按钮（项目管理 / 布局 / 导演包 / 导出 / 资源库）收进 **··· 更多** 菜单，项目会话一屏只留必要的视图与运行操作。

|---|---|
| **▦ 概览** | 六步路线图、故事来源、项目信息、快捷入口、当前步骤操作台 |

**原著数据与原文**：`management.source.text` 是全文唯一权威落点。新增 `GET /api/projects/:id/source`，由 `src/core/source-view.mjs · buildSourceView()` 汇总总字数 / 章节数 / 段落数 / 分集数 / 季数 / 角色数，并重建章节目录与来源文件关联；历史项目里 `chapters=[]`、`sources=[]`、`episodes[].text=''` 也能惰性重建。若服务是改动前启动的旧进程（接口返回 404），前端用 `public/project-model.js · localSourceView()` 做等价回退，统计、章节与全文照常可读。阅读器默认展示**完整导入原文**，可切按章、跳转剧集、搜索高亮。

**分季分集**：季是轻量分组，不改既有全局唯一集号 `no` —— `ep.season` 缺省为 `1`，`management.seasons[]` 只存季号与标题，老项目自动归入「第 1 季」。可新增季、重命名季、删除季（该季的集退回第 1 季）、把任意集移到另一季；侧栏剧集树、页脚统计与画布范围下拉按季实时同步。

**每集独立无限画布 + 全部组合画布**：画布顶部新增范围条，三种范围共用一个 `CanvasController`：

| 范围键 | 含义 | 数据落点 |
|---|---|---|
| `overall` | 全部组合画布 | `composeOverallCanvas(project)` **派生只读**，不落盘 |
| `main` | 项目主画布 | `project.nodes / edges / viewport` |
| `ep:<no>` | 第 N 集自己的画布 | `management.episodes[n].canvas = { nodes, edges, viewport }` |

> 组合图按 600 节点上限裁剪以保证大图可交互；实测 8 集项目组合约 250 节点 / 417 连线，`⤢ 适应视图` 缩到约 10% 属总览定位，放大即可看细节。

### 项目封面

项目列表页的项目卡左侧显示封面缩略图，有三种来源，可在卡片菜单「🖼 设置项目封面」、项目侧栏「项目设置 → 项目封面」或管理面板「概览 → 设置项目封面」里切换：

- **项目名称封面（默认）** — 未设置时按项目名哈希生成稳定渐变色块 + 首字，无需任何外部资源；
- **上传本地图片 / 资源库选用** — PNG / JPEG / WebP / GIF，≤4 MB，写入 `data/assets` 后立即可见；
- **ComfyUI 生成** — 用已配置的出图工作流生成封面，支持**多张参考图**（资源库多选 / 本地上传，按顺序对应工作流的多个 `LoadImage` 插槽）。

提示词支持**「✦ AI 生成提示词」**：调用项目配置的 LLM（设置 → 模型），按项目名称、简介、剧本梗概与小说总结自动生成一版可编辑的文生图提示词；未配置模型或调用失败时回退内置模板，响应里明示来源。**文本框内容即完整提示词，生成时原样使用（不自动套片名 / 风格模板）**；留空才按项目资料自动生成。

生成期间弹窗显示忙碌遮罩并禁用关闭；上传 / 生成 / 恢复名称封面都会写入项目管理历史，并同步刷新项目列表页索引与项目侧栏封面。

点「▶ 一键完成最终产物全流程」后，导演智能体依次执行：

1. **前置保障**：没有原著时按一句话构想生成演示小说并自动分集（零 Key 标 `mock`）；既没有原著也没有构想则明确阻断，不产生「六步全 done 但空画布」的假成功。
2. **技能能力**：按所选策略调用真实业务 Agent——导演阐述写入 `management.director.treatment`、角色提取、角色定妆、音色分配；未配置模型一律标 `heuristic`，不冒充 LLM 成果。**选了导演风格时，阐述以该风格的视听语法为基线**（主色、光线、构图、运镜、连戏约束），通用模板只能补标题与一句话梗概。
3. **制作链路**：按技能的步骤范围调用 `executeSteps`，复用六步状态机与画布编排器，节点随每步实时生长。
4. **收尾与验收**：补齐 / 重打 `*.mmxpack.zip` 导演包，逐项核对原著、剧本、上下文、分镜、六步状态、导演包与成片；报告落在 `management.director.lastRun`。**「⑦ 成片交付」顶部展示的是实时验收**（`verifyDirectorDeliverables` 随单项目 GET 与 `project:meta` 广播实时计算，六步完成、剧本 / 分镜产出后立即翻绿，不依赖重跑导演流程）；`lastRun` 作为「上次导演全流程报告 · 历史快照」折叠展示，不再把跑完那一刻的旧结果当成当前状态。**真实策略下缺真实 AI 片段一律判「缺失」；预览策略下成片与 ComfyUI 片段如实标「降级」并写明原因，都不计为成功。**

风格真实生效走四层链路：档案数据（`director-styles.mjs`）→ 项目状态（`management.director.styleId` + `paletteKey`）→ 项目级解析（`resolveProjectAesthetic` → `settings.aesthetic`）→ 生成侧消费（正向风格串 + 固定否定词、Mock 调色板 `accent`、分镜的 `ffDesc` / `motionDesc` / `audioDesc` 带主色光线媒介）。零 Key 环境下十位导演的阐述、配色、运镜、音频**两两不同**，由测试固化。

REST：`GET/POST /api/projects/:id/director/skills`（清单 / 选择风格或流程策略 / 切换主色调 / 运行计划 / 验收快照）、`POST /api/projects/:id/director/run`（一键全流程）。选择接口接受中文名（`张艺谋` 与 `zhangyimou` 等价），拼错明确拒绝。运行期通过 SSE `director:progress` 实时推进工作台进度条；`/api/bootstrap` 下发 `directorSkills` / `directorSkillGroups` / `directorCapabilities`，智能体列表里也注册了 `director` 一等公民。

### 短剧成片规格：常用规格可点选 + 全字段可自定义

`src/core/runtime-spec.mjs` 把「总时长 ÷ 每片段时长 → 片段数」做成项目级单一事实来源，默认 **30s / 3s = 10 个片段 @ 24fps（720 帧）**。

工作台「① 设置基础信息」的规格区不再只有两个裸数字框（用户只能凭感觉敲数，也不知道 30s 究竟对应几个片段）：

- **5 条常用规格一键套用**：30s 预告（10×3s）/ 60s 短剧（20×3s）/ 90s 短剧（18×5s）/ 2 分钟（24×5s）/ 3 分钟（36×5s）；命中哪条就把哪张卡点亮，改了任一字段立刻转为高亮的「自定义」，不会让用户误以为还在预设上。
- **每个字段都能选**：总时长可直接输；每片段在 2/3/4/5/6/8 秒里选，标准档位外还能选「自定义…」露出秒数输入框（历史项目的 7s、7.5s 原样保留，不被下拉框悄悄改成档位值）；帧率 24/25/30；**成片模式** `real`（真实 AI 视频）/ `preview`（关键帧预览）也可在界面上选，切到预览时说明文字变琥珀色警示。
- **即时等式与对齐提示**：编辑过程中实时显示 `105s ÷ 5s = 21 个片段 · 24fps · 2520 帧`，不能整除时明确写「总时长按 5s 对齐为 105s」；旁边标注当前画幅与单帧分辨率（16:9 → 864×480，9:16 → 480×864）。
- **改动未保存有标记**：点完预设但没保存时，「保存规格」按钮描边变强调色并带圆点，标题栏徽标同步显示生效值。

前端推算 `previewRuntimeSpec()`（`public/project-options.js`）与后端 `normalizeRuntimeSpec()` 逐字段同口径，`tests/runtime-presets.test.mjs` 用 7 组输入（含小数、超限、非整除）做交叉断言，保证「界面预览的片段数 = 保存后落盘的片段数」。

保存后下一次「一键完成最终产物全流程」按新片段数重新分配镜头预算。此前片段时长散落在 5 处硬编码（分镜 `4+(i%3)`、视频默认 5s、时间线默认 5s、拼接默认 5s、单集导演包固定 5s），结果 30s / 3s 无法表达，系统甚至会把「12 片段 / 4·5·6s / 60s」判成「全流程已达成」。现在规格贯通全链路：

| 环节 | 实现 |
|---|---|
| 片段数推导 | `normalizeRuntimeSpec()`：片数由总时长与片段时长推导，不独立存储；不能整除时按片段时长对齐总时长并标记 `aligned` |
| 镜头预算 | `allocateShots(sceneCount, spec)` / `shotSequenceStarts()`：把 `clipCount` 精确分配到各场景，全片镜头总数恒等于片段数，并用全局序号稳定排序 |
| 单片段时长 | 分镜 mock、`video` Agent、`composer` 时间线、导演包 `collectShotPackages()`、单集包 `timeline.json` 全部同源 |
| 成片 | 真实 ComfyUI 片段 → `stitchClips()`（ffprobe 实测）；零 Key → `renderPreviewFilm()` 用本机 ffmpeg 把关键帧渲染成 10 个 3s 片段拼成 30s MP4，明确标 `source: 'preview-frames'`（**关键帧预览成片，不是 AI 生成视频**） |
| 验收 | `verifyDirectorDeliverables()` 新增「成片时长规格」项，逐条核对片段数 / 每片段时长 / 时间线总长 / 导演包组数 / MP4 实测时长，任一不符即 `missing` |

REST：`GET/POST /api/projects/:id/runtime`（规格快照 / 保存 / 片段时间线 / 验收；`POST` 接受 `totalSeconds` / `clipSeconds` / `fps` / `filmPolicy` / `enabled`，只提交的字段才覆盖，非法值一律 400 不静默回落）；`/api/bootstrap` 下发 `runtimeDefaults`。实测产物：`30s 短剧 · 雨夜便利店` 项目 10 片段 × 3s = 30s，导演包 `timeline.json` 10 段 / 720 帧，成片 MP4 经 ffprobe 实测 30.00s，验收清单 8 项全达成。

### 成片真实性策略：不调用 ComfyUI 就不算真实短剧

`src/core/film-policy.mjs` 把「成片是不是 AI 真实生成」做成可核对的一等公民，杜绝此前「ComfyUI 一次没调用，却用 ffmpeg 关键帧拼一条 MP4 冒充 30s 成片还判全达成」的问题：

- **`real`（默认）**：每个片段必须由 ComfyUI 视频工作流生成（`provider === 'comfyui'` + 真实视频文件 + 未标合成预览），成片必须由真实片段拼接；少一段、或成片是 `preview-frames`，验收一律判 **缺失**。
- **`preview`**：显式切换才启用（「使用关键帧预览模式」），产物标注「非 AI 视频」，验收记 **降级**。
- 验收新增第 9 项「ComfyUI 真实 AI 片段」：逐片段核对 provider 与文件，`prompt_id` 全部留痕可追溯。

### AI 制片对话：每一步都能在对话框里完成

小说合成短剧的全部操作都可以用一句中文在对话里完成，改的就是真实业务状态（与 UI 按钮同一条链路），不是聊天玩具：

| 层 | 入口 | 能做什么 |
|---|---|---|
| 分步对话 `src/core/step-chat.mjs` | 工作台每一步的「💬 对话」按钮（含项目总助理） | 改创作设定 / 分集策略 / 集标题 / 角色属性 / 音色 / 成片规格 / 交付物 / 切成片策略 / 重跑本步或剩余步骤；顶部常驻 token 账目（执行 / 对话 / 合计 + 运行明细） |
| 制片对话 `src/core/production-chat.mjs` | `POST /api/projects/:id/production/chat` | 跨步单会话：状态 / 准备小说 / 规格 / 策略 / ComfyUI 自检 / 技能 / 角色 / 音色 / 单步 / 六步 / 一键全流程 / 验收 / 导演包 / 成片 / 导出记录 |

- **全量留痕**：每条消息带意图、参数、实际调用的接口与等价 `curl` 命令，按步落盘 `data/conversations/{projectId}.step-{stepId}.json`，项目内 `management.stepChats` 双写。
- **复刻导出**：`GET /api/projects/:id/steps/:stepId/chat/export?format=md|json` 与 `/production/chat/export` 生成 Markdown（对话全文 + 按顺序的一键复刻命令串 + 环境要求）与可脚本重放的 JSON，发给其他用户即可照着重跑。
- **token 分账**：重跑步骤的消耗记在 `step.tokens`，对话本身的消耗记在 `step.chatTokens`，`GET /steps/tokens` 出每步明细。

## 桌面版安装与分发（Electron 打包）

源码形态（`node server.mjs`）之外，项目可用 electron-builder 打成 mac / Windows / Linux 安装包；数据目录自动切换到各 OS 的用户数据目录（macOS `~/Library/Application Support/lingximanju`、Windows `%APPDATA%\lingximanju`、Linux `~/.config/lingximanju`），与源码形态的 `data/` 互不影响。

### 打包命令

```bash
npm install          # 首次需要：安装 electron / electron-builder（均为 devDependencies）
npm run dist:mac     # 产物：release/*.dmg + release/*-mac.zip
npm run dist:win     # 产物：release/*.exe（NSIS 安装器）
npm run dist:linux   # 产物：release/*.AppImage + *.deb
```

- 若 npm 拦截了 electron 的 postinstall（安装脚本白名单机制），补执行一次 `node node_modules/electron/install.js`。
- 本地开发预览桌面版：`npm run electron`。
- 默认 `--publish never`，只打包不发布；当前 mac 产物为 Apple Silicon（arm64）版本，Intel 机器用 `npx electron-builder --mac --x64 --publish never`。

### mac 安装与首次启动（未签名版本）

安装包未做 Developer ID 签名（Apple Silicon 上 electron-builder 已自动 ad-hoc 签名，可正常运行），仅 Gatekeeper 会拦截**首次**启动：

1. 双击 dmg，把 **lingximanju.app** 拖进「应用程序」
2. 首次启动：**右键点击 app → 打开 → 再点「打开」**
3. 若系统较新（macOS 15+）右键仍被拦：**系统设置 → 隐私与安全性** → 底部「lingximanju 已被阻止」→ 点 **仍要打开**
4. 仅首次需要，之后双击即可正常启动

如需正式分发（双击即开、无安全提示），需加入 Apple Developer Program（99 美元/年）申请 **Developer ID Application** 证书，electron-builder 检测到钥匙串中的证书后会自动完成签名与公证。

| **项目工作台** | 进入创作项目后的默认整页视图，按编号步骤顺序单页展示：**① 设置基础信息 → ② 准备故事 → ③ 分集拆解 → ④ 剧本创作 → ⑤ 角色与上下文 → ⑥ 分镜与画面 → ⑦ 成片交付**；1–N 步骤导航是**悬浮在步骤卡之上的可折叠浮层**（圆角阴影、滚动时固定），点 `⟨` 收起为左上角悬浮胶囊，胶囊显示 `完成数/总数` 与当前步骤名并随滚动联动，点胶囊重新展开；展开 / 收起状态写入 localStorage，切换不重建 DOM、不会丢失正在编辑的表单；窄屏（≤1080px）自动回落为顶部横向步骤条，收起时只折叠列表、保留标题条；导航含完成进度与「下一步」标记，点击平滑滚动到对应步骤；原著阅读、分季分集管理、资源归纳分别融入 ② / ③ / ⑦ 步骤内；**步骤卡片铺满工作台内容区**（不设 `max-width` 居中上限：展开 / 收起两态都从工作台最左边铺满到右边缘）；制作步骤浮层**纯悬浮覆盖在左侧内容之上**（`position:fixed`、`z-index:40`、贴工作台左上角，滚动时固定不动），内容不再为它让位，收起后遮挡自动解除；每个步骤带状态药丸与「▶ 执行本步」按钮，底层仍走六步任务状态机；顶栏 `V` 与画布互切 |
| **原著统计与阅读** | 导入小说后展示六项统计（总字数 / 章节 / 段落 / 分集 / 季 / 角色），支持全文或按章阅读、章节目录、搜索高亮、复制 / 下载 / 重新导入；`GET /api/projects/:id/source`，改动前的旧服务由前端 `localSourceView()` 等价回退 |

## 边界说明

- **创作项目是 lingximanju 内部的一类项目**，不是独立应用：上传小说、分集、六步任务、项目管理都复用同一套画布、编排与产物链路，无限画布引擎未改动；工作台只是画布之上的「引导层」，所有操作最终落到同一份项目 JSON。
- **AI 生成小说不是「一键成片」**：它替代的是「写原著」这一步——大纲与正文由已配置的 LLM 生成（未配置时用内置模板演示），之后的剧本、分镜、画面仍走原有六步流水线。
- **分集层是论文之外的扩展**：论文以 8–16 镜头短片为尺度，本项目为长篇小说增加「集」这一中间粒度；其余六步逐条对应式(1)–(8)，见 `docs/THEORY.md`。
- **Mock 模式**产出的是可预览的分镜 SVG 与关键帧序列预览，用于完整演示编排、依赖传播与一致性机制，**不是真实视频文件**；产品内也明确标注了这一点。
- **图片 / 视频主路径依赖本机 ComfyUI**：未导入工作流时自动回退 Mock；导演包内的 SVG 槽位图会渲染成合法 PNG 占位，并在 `manifest.json` 与界面中标注，接入出图工作流后自动替换为真实画面。
- **导演包是交接格式，不是渲染器**：它把分镜、首帧、角色参考与完整时间线交给 ComfyUI 导演工作台，视频由对方生成；本项目不内置 MiniMax H3 模型权重与自定义节点。
- ffmpeg 拼接为可选增强，本机缺少 ffmpeg 时保留逐镜头片段与下载入口。
- 未实现 3D 导演台、插件市场、MCP、移动端、多用户协作——这些不属于本次「功能复刻 + 无限画布」的范围。
- 真实出片质量取决于接入的图像/视频模型；框架负责编排、一致性与效率，不提升底座模型本身的画质。
