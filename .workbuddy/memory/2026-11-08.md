## 代码结构整理：共享工具层与纯函数边界

- 需求：优化整理代码结构。选择「不移动任何现有文件路径、不改业务流程」，避免与工作区未提交的并行改动冲突，也保住 git 历史。
- 调研发现：`esc` 在 14 个前端模块重复定义且两种转义强度（是否转 `'`）；`cut` 在 9 个模块重复且两种截断语义（输出 n+1 / ≤n）；`num/clamp/uid/fmt/str/escapeRegExp` 各有 2–3 份；画布范围规则散在 `app.js` 的 DOM 函数里不可单测；`styles.css` 1769 行缺全局导航。
- 新增 `public/utils.js`（零依赖、顶层不碰 DOM）：统一 `str / esc(escapeHTML) / cut / num / fmtNum / fmt / clamp / uid / escapeRegExp / $`。新增 `public/canvas-scope.js`（只依赖 project-model）：`EMPTY_CANVAS_PROJECT / groupScopeOptions / scopeOptionsSignature / scopeHint / isScopeReadOnly`。
- 19 个模块改为共享导入，删约 53 行重复定义；`app.js` 范围 UI 改用纯函数、`scopeReadOnly()` 改调 `isScopeReadOnly()`；清掉 `wizard.js` 未使用的 `esc` 死代码；`styles.css` 加 10 段分区目录与命名约定（未改任何规则）。
- 统一口径：`esc` 转 `'`（更安全）、`cut` 输出 ≤n 且省略号计入 n；`uid` 补单调递增序列，修掉同毫秒高频调用约 7% 碰撞（新单测曾偶发失败）；`EMPTY_CANVAS_PROJECT` 不冻结以免空态写入行为变化。
- 分层约定：`utils.js`（零依赖）← 纯函数层（project-model / canvas-compose / canvas-scope）← 视图与引擎层 ← `app.js` 编排；新模块顶层不碰 DOM，可被 node:test 直接导入。
