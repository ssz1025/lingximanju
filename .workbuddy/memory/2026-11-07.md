## 工作区门户新增项目：InkOS（Narcooo/inkos）

**需求**：把 https://github.com/Narcooo/inkos.git 加入 `05-AIGC调研` 门户并本地部署。

**落地**
- 源码浅克隆到 `05-AIGC调研/inkos/`。GitHub 直连在本环境被 SSL 拦截，且全局 git 有 `ghproxy.net` 重写规则；可用方案：`GIT_CONFIG_GLOBAL=/dev/null git clone --depth 1 https://gh-proxy.com/https://github.com/Narcooo/inkos.git`。
- 运行时用 npmmirror 本地安装 `@actalk/inkos@1.8.0` + `tsx@4.23.15` 到 `inkos/runtime/`；Node 22.22.2 满足项目要求 ≥22.16。源码是仓库快照（package.json 2.0.0），运行时用 npm 稳定发行版 1.8.0。
- 门户四件套：`index.html` 新增卡片、`inkos.html` 详情页（一键启动/停止/状态）、`server.py` 的 `PROJECTS["inkos"]`（端口 4567）、新增 `inkos_launch.sh`；部署产物用 `inkos/.git/info/exclude` 排除。
- **关键坑 1**：数据目录必须与源码仓库**平级**（`05-AIGC调研/inkos-workspace/`）。CLI 的 `resolveStudioLaunch` 会检查 `root/../packages/studio/src/api/index.ts`，命中就切到源码开发模式，因 monorepo 未装依赖（缺 hono）而启动失败。
- **关键坑 2**：启动脚本要 `env -u NODE_OPTIONS` 去掉 WorkBuddy 注入的 Node 文件代理，否则 npm 批量落盘/运行时会 `CODEBUDDY_BROKER_OUTCOME_UNKNOWN` 超时；再加 `npm_config_yes=true` + npmmirror + PATH 带 `runtime/.bin`，避免 npx 卡在交互确认。
- bash 脚本里 `$VAR` 后紧跟中文会在 C locale 下被并进变量名（unbound variable），统一写 `${VAR}`。

**验证**：门户 8765 首页 / 详情页 / 源码 README 均 200；Studio 4567 返回 200；一键停止 → 端口释放 → 再启动闭环通过。Studio 需在其服务页配置 LLM 服务商与 API Key 才能真正写作；许可证 AGPL-3.0-only（对外提供网络服务需注意开源义务）。
