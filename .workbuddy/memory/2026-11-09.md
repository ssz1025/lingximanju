**发现并修复 1 个真实缺陷**（`public/project-manager.js`）：
- 现象：打开「项目管理 → 角色」，已绑定音色的角色显示「未分配音色」、试听按钮 disabled、抽卡候选区空白；随便点一下（触发任意交互）才恢复正常。

**环境坑（复跑须知）**：
- 无头 Chrome `--dump-dom`/`--screenshot` **不能加** `--virtual-time-budget` 配 `setTimeout` 轮询：虚拟时间会快进定时器却不等真实网络，轮询被瞬间跳过 → 拿到空壳 DOM。解法是用 `await fetch('/api/health')` 做真实网络轮询；或让探针脚本用 top-level await 直接 `await handle.refresh()`。
- ES module 的 top-level await 不阻塞 `load` 事件，故 `--dump-dom` 需配 `--virtual-time-budget` 才能等到模块跑完。
- 页面有常驻 SSE（`/api/events`）时 `--dump-dom` 会等到超时；探针页不连 SSE 即可。
- 首页/项目页无 hash 路由，无头模式点不了按钮 → 用**临时探针页**放 `public/` 里 `import` 真实前端模块渲染目标面板，验完删除（已删净，`npm run check` 132 文件通过）。

## 音色抽卡 · 用户体验与流程优化（试听态 / 绑定正确性 / 命名 / 数量）

**修掉 4 个真实缺陷（都是端到端跑出来才发现的）**

1. **`isSpeaking()` 误判「没在播」（`public/voice-preview.js`）**：原实现 `if (_audio) return !_audio.paused && !_audio.ended;` —— `<audio>` 单例一旦建过就一直在，之后用**浏览器 SpeechSynthesis** 朗读时它处于 paused，导致「在播」被误判为 false，播放态按钮永远出不来。改为「`_audio` 在播 **或** `speechSynthesis.speaking` 都算在播」。由新写的 `tests/voice-preview.test.mjs` 抓出。
2. **展开「音色库管理」整页渲染中断（`public/project-manager.js` `voiceEditorHTML`）**：`esc((e && e.tags) || []).join('，')` —— `esc()` 返回字符串，再 `.join` 抛 `TypeError: esc(...).join is not a function`。因为模板里 `voiceLibOpen ? voiceLibBodyHTML() : ''`，默认折叠时永不求值，所以只在用户点「展开」时炸。**既有缺陷**，但「保存候选后自动展开音色库」的改动会把它放大成主路径，必须修：改为 `esc(((e && e.tags) || []).join('，'))`。
3. **候选静默绑错角色（`voiceCandidatesHTML`）**：`const bindTo = d.characterId && target ? target.id : (chars[0]?.id || '')` —— 候选没带 `characterId`（来自全局 `/api/voices/draw`）时回退到**第一个角色**，「保存并绑定」会把音色绑到毫不相干的人身上且用户看不出来。改为：只有「当初就是为这个角色抽的」才预填；否则渲染「绑定到角色…」选择器（未选时按钮 disabled），用户必须显式指定。
4. **原生 select 白底白字（`public/styles.css`）**：`.pmm-voice-select` 只有 `flex:1;min-width:180px`，没有背景/边框/文字色 → macOS 渲染成白底，选中值几乎不可见；候选卡新增的 `.pmm-draft-bind-target` 同病（被看成「空白小方块」）。统一补 `background:var(--panel); border; color:var(--text)`。
